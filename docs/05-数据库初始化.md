# 4. 数据库初始化

## 创建数据库和用户

先将本地的 `schema.sql` 上传到服务器 `/opt/ai-hardware/schema.sql`，然后：

```bash
# 以 root 身份进入 MySQL
mysql -u root -p
```

执行以下 SQL：

```sql
-- 创建数据库
CREATE DATABASE ai_hardware CHARACTER SET utf8mb4;

-- 创建专用用户（不要用 root 连接业务数据库）
CREATE USER 'ai_hw'@'localhost' IDENTIFIED BY '你的强密码';

-- 授权
GRANT ALL ON ai_hardware.* TO 'ai_hw'@'localhost';
FLUSH PRIVILEGES;
EXIT;
```

## 为什么要创建专用用户？

- `root` 用户权限太大，如果应用被攻破，攻击者可以操作所有数据库
- `ai_hw` 用户只能操作 `ai_hardware` 这一个数据库，即使泄露也不会波及其他数据
- `@'localhost'` 表示只允许本机连接，外部无法远程登录

## 导入表结构和初始数据

```bash
mysql -u ai_hw -p ai_hardware < /opt/ai-hardware/schema.sql
```

- `-u ai_hw`：用 ai_hw 用户登录
- `-p`：提示输入密码
- `ai_hardware`：指定要导入的数据库
- `< schema.sql`：将 SQL 文件内容导入执行

## 验证导入是否成功

```bash
mysql -u ai_hw -p ai_hardware -e "SHOW TABLES;"
```

应该能看到所有业务表列表。

## 踩坑：SQL 语法报错

**报错信息**：

```
ERROR 1064 (42000) at line 413: You have an error in your SQL syntax
```

**原因**：INSERT 语句的最后一条数据以逗号 `,` 结尾，而紧接着的下一条数据被注释掉了，导致整个 INSERT 没有分号 `;` 结束。

**错误示例**：

```sql
INSERT INTO `news` VALUES
('文章1', ...),
('文章2', ...),    -- ← 这里的逗号是问题所在
-- ('文章3', ...);  -- 这条被注释了，但上面的逗号还在
```

**修复**：把最后一条有效数据末尾的逗号改成分号：

```sql
('文章2', ...);    -- ← 改成分号
```

> **经验**：注释掉 INSERT 中的某些行时，一定要检查前一行的逗号是否需要改成分号。

## 本地用 Navicat 连接服务器数据库（SSH 通道）

部署完成后，如果想在本地用 Navicat 查看 / 操作阿里云上的数据库，**推荐使用 SSH 通道**，不用开放 3306 端口到公网。

### 为什么必须走 SSH 通道

按本教程配置，默认无法直接连接数据库，有三重拦截：

1. **阿里云安全组**只开放 80/443/22，没开 3306
2. **MySQL 用户** `'ai_hw'@'localhost'` 只允许本机连接
3. **MySQL 默认** `bind-address=127.0.0.1`，不监听外网

SSH 通道的原理：Navicat 先 SSH 登录服务器，再从服务器内部访问 `localhost:3306`，相当于你"人在服务器上"操作数据库。只借用已经开放的 22 端口，不用改 MySQL 配置，最安全。

### Navicat 配置

**常规** 标签（连接 MySQL）：

| 字段 | 值 |
|------|------|
| 主机 | `127.0.0.1` |
| 端口 | `3306` |
| 用户名 | `ai_hw` |
| 密码 | application-prod.yml 中配置的密码 |

**SSH** 标签（勾选「使用 SSH 通道」）：

| 字段 | 值 |
|------|------|
| 主机 | 阿里云服务器公网 IP |
| 端口 | `22` |
| 用户名 | `root` |
| 验证方法 | 密码 / 公共密钥（二选一） |
| 密码 | 重置后的 root 密码（密码方式） |
| 私钥 | 阿里云下载的 `.pem` 文件（密钥方式） |
| 通信短语 | **留空**（阿里云创建的密钥对默认无 passphrase） |

### 「通信短语（Passphrase）」是什么

这是给**私钥文件本身**加的密码，**不是服务器密码**：

- 阿里云控制台创建的密钥对默认**没有通信短语**，留空即可
- 只有你在本机用 `ssh-keygen` 主动生成密钥并设置了 passphrase 才需要填

点 **测试连接** 验证两个标签页都成功即可使用。
